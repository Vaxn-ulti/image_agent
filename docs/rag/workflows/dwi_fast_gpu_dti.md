# DWI Fast GPU DTI Workflow RAG

## Scope

Use this document when the user asks about the production Image Agent DWI workflow, DTI maps, DWI QC/report images, DWI eligibility, or why production DWI is not full QSIPrep/QSIRecon.

This document is workflow interpretation support. It does not replace backend task records, `/tasks/{task_id}/result-summary`, or artifact metadata.

## Workflow Purpose

`dwi_fast_gpu_dti` is the current production DWI path for bounded-runtime scalar DTI outputs. It produces FA/MD/AD/RD maps, MNI152-space maps when registration or fallback resampling succeeds, regional DTI tables, provenance, QC files, and report figures.

It is not full QSIPrep and not full QSIRecon. The workflow uses:

- host FSL for GPU eddy correction and registration checks, including `eddy_cuda`, `flirt`, `dtifit`, `applywarp`, and `fslmaths` availability;
- MRtrix commands from the `pennlinc/qsiprep:latest` image as a toolbox, including `dwi2mask`, `mrconvert`, `dwi2tensor`, and `tensor2metric`;
- backend result-summary and artifact registration for user-facing outputs.

## Expected Inputs

- DWI NIfTI.
- `.bval` and `.bvec` sidecars.
- JSON sidecar with `PhaseEncodingDirection` and `TotalReadoutTime` so the backend can derive eddy acquisition files.
- Task-scoped output/work directories.
- Runtime access to host FSL and the MRtrix toolbox image.
- Template/atlas resources for MNI152 maps and regional DTI tables.

If the JSON sidecar or phase-encoding/readout metadata is missing, block validation or launch. Do not fabricate `acqparams.txt`, `index.txt`, phase-encoding direction, or readout timing.

## Expected Outputs

Primary structured outputs should come from `/tasks/{task_id}/result-summary`.

Expected artifact families:

- native FA/MD/AD/RD scalar maps;
- MNI152 FA/MD/AD/RD maps when registration or fallback resampling succeeds;
- atlas regional TSV tables and combined regional DTI tables;
- `qc/qc_report.tsv`;
- `qc/dwi_fast_gpu_dti_provenance.json`;
- `summary/dwi_result_summary.json`;
- scientific report bundle entries under `outputs.reports`, including `dwi_tensor_metrics.png` and `dwi_atlas_region_means.png` when generated by the report builder.

## Result-Summary Reading Hints

- Trust backend task state and result-summary before RAG text.
- Use `feature_groups`: `native_dti_maps`, `mni152_dti_maps`, `regional_dti`, `qc`, and `scientific_report`.
- Preserve provenance flags such as `full_qsiprep_run: false` and `full_qsirecon_run: false`.
- If `validation_only=true`, describe preflight/readiness only; do not claim scientific DTI outputs.
- If provenance records finite-map sanitization or replacement counts, mention the recorded provenance rather than inventing image-quality claims.
- If MNI registration fell back to header-based resampling, describe the fallback exactly as provenance records it.

## Container-Native DWI QC and Display

For this workflow, container-native DWI QC means backend-registered maps, tables, QC TSVs, provenance JSON, logs, and any native/report-builder artifacts derived from the DWI processing toolchain. Report-builder PNGs are secondary presentation assets, not decorative substitutes and not replacements for missing native workflow evidence.

Display priority:

1. `outputs.reports` for HTML/report bundles and previewable report PNG assets.
2. `outputs.figures` when native QC/report assets are registered there.
3. `outputs.tables`, `outputs.maps`, and `outputs.logs` for inspection and download.

The console DWI result panel should surface `dwi_tensor_metrics.png` beside the tensor map matrix and `dwi_atlas_region_means.png` beside atlas regional outputs when those report figures are registered. These report-builder images should carry `source_stage: scientific_report`, `artifact_role: derived_presentation_asset`, `artifact_origin: generated_from_result_summary`, `native_artifact: false`, and `provenance.replaces_native_qc: false`. Desktop result summaries already render native QC figures from `outputs.reports` and `outputs.figures`.

Do not replace missing DWI QC/report artifacts with model-generated images. Missing report figures are a report/artifact-registration gap, not proof that the underlying maps or tables failed.

## Boundary Notes

- Do not describe production DWI as full QSIPrep or QSIRecon.
- Do not cite raw HTML snapshots directly to users; raw snapshots are traceability evidence only.
- Do not expose patient identifiers, raw image contents, full sensitive paths, license text, API keys, sudo passwords, or bearer tokens.
- Do not infer diagnosis, dementia status, prognosis, or treatment recommendations from FA/MD/AD/RD values.

## Good Agent Answer Pattern

1. Start from backend task status and result-summary.
2. State whether the task is real, validation-only, failed, or incomplete.
3. Summarize produced artifact families: native maps, MNI maps, regional tables, QC/provenance, report figures.
4. Preserve the production boundary: host FSL plus MRtrix toolbox mode, not full QSIPrep/QSIRecon.
5. Mention registered native report images from `outputs.reports` when present.
6. Add non-diagnostic safety language for any user-facing interpretation.
